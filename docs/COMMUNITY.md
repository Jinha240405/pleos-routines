# 루틴 커뮤니티 · 0.6

사용자가 현재 루틴을 설명·닉네임·분류와 함께 게시하고, 다른 브라우저 또는 Pleos 앱에서 내 루틴으로 내려받는 로컬 커뮤니티입니다. 계정 서비스나 공개 호스팅은 아직 사용하지 않습니다.

## 시작

Node.js 22 이상에서 실행합니다.

```powershell
npm ci
npm run dev
```

- 편집기와 커뮤니티: http://127.0.0.1:5173
- 커뮤니티 JSON 서버: http://127.0.0.1:8787
- 게시물 저장: `.community-data/posts.json` (Git 제외)

`npm run dev`는 두 서버를 함께 실행합니다. 종료 후 다시 실행해도 게시물은 남습니다. 다른 브라우저나 시크릿 창에서 같은 주소를 열면 별도 사용자의 업로드·다운로드를 확인할 수 있습니다.

빌드된 웹앱만 서비스하려면:

```powershell
npm run build
npm start
```

이때 http://127.0.0.1:8787 에서 웹앱과 API를 함께 제공합니다. `COMMUNITY_PORT`, `COMMUNITY_DATA_DIR`로 포트·저장 경로를 바꿀 수 있습니다. `npm start`는 기본적으로 이 컴퓨터에만 연결을 허용합니다. 같은 네트워크에 연결할 경우 `COMMUNITY_HOST=0.0.0.0`과 호스트 방화벽을 별도로 설정해야 합니다. 외부 인터넷 공개 전에는 HTTPS, 계정·운영자 관리, 신고·게시물 관리, 저장소 백업이 필요합니다.

## Android

디버그 APK는 에뮬레이터의 호스트 주소 `http://10.0.2.2:8787`에 연결합니다. 컴퓨터에서 서버를 켜 두세요. 원격 HTML을 WebView에 로드하지 않고 `CommunityApi`가 JSON만 가져옵니다. 에뮬레이터 호스트 주소에만 디버그 HTTP 예외를 두며, 릴리스는 HTTPS 서버 주소를 정하기 전까지 커뮤니티 연결을 비활성화합니다.

커뮤니티 서버를 끄면 기존 내 루틴과 기본 템플릿 편집은 계속 가능합니다. 브라우저에서 차량 실행은 비활성화하며 가상 성공 응답을 만들지 않습니다. 실제 실행과 상태 감지는 Pleos 앱에서만 제공합니다.

## 사용자 흐름

1. 내 루틴에서 공유할 루틴을 열고 편집합니다.
2. 커뮤니티 → **내 루틴 올리기**에서 닉네임, 분류, 설명을 작성합니다.
3. 블록에 포함된 주소·좌표·이름·안내 문장을 확인하고 게시합니다. 기기의 센서 조회 결과나 실행 기록은 포함하지 않습니다.
4. 다른 사용자는 검색·분류·최신순·다운로드순으로 찾습니다.
5. 상세에서 사용 기능과 설정을 확인하고 **내 루틴에 내려받기**를 누릅니다.
6. 로컬 사본을 편집합니다. 내려받기 자체로 실행·상태 감지가 켜지지 않습니다.

계정 인증 대신 기기에 생성·저장한 256비트 키로 게시물 소유권을 구분합니다. 서버에는 키의 해시만 저장하며 목록에 공개하지 않습니다. 닉네임은 인증된 신원이 아닙니다. 브라우저 저장소 또는 앱 데이터를 삭제하면 기존 게시물을 삭제할 권한도 잃습니다. 다운로더가 저장한 사본은 원본 게시물 삭제와 별개입니다. 다운로드 숫자는 다운로드 요청 횟수이며 고유 사용자 수가 아닙니다.

## 현재 블록만으로 만든 기본 루틴

| 루틴 | 조합 | 사용자가 바꿀 부분 |
|---|---|---|
| 빈 동승석 정리 | 좌석 변화 감지 + 빈자리 + P단 → 열선·통풍·독서등 끄기 | 좌석 위치, 끌 기능 |
| 충전 후 출발 준비 | P단 + 목표 충전량 비교 → 공조·통풍 또는 충전소 화면 | 70% 기준, 온도·풍량·통풍 |
| 차박 독서 자리 | P단 → 앞자리 독서등 끄기 + 뒷자리 한 곳 켜기 + 약한 바람 | 조명 위치, 풍량 |
| 도착 후 다음 일정 | 내비 도착 이벤트 + 배터리 비교 → 충전소 또는 내 할 일 읽기 | 45% 기준, 안내 문장 |
| 캠핑 철수 브리핑 | P단 + 창문 4곳·적재함·배터리 조회 → 확인할 항목을 문자열로 모아 한 번 읽기 | 40% 기준, 장비 목록 |

새 실행 블록이나 지속 상태를 추가하지 않았습니다. 정차 전용 예시는 P단 확인 실패 시 제어하지 않습니다. API 미지원·권한 오류가 나면 실행을 중단하므로 해당 기능을 제거하거나 차종에 맞게 수정해야 합니다. 감지형 루틴은 현재 루틴 화면이 활성화된 동안만 동작합니다. 시동·유틸리티 모드 유지나 야간 백그라운드 실행을 보장하지 않습니다. API 카탈로그와 실행 엔진 검증은 실제 차량에서의 지원 검증을 대신하지 않습니다.

## 서버 구성

- 표준 Node HTTP 서버, 외부 DB 의존성 없음.
- 루틴 JSON 스키마와 허용된 블록/API를 검증. 임의 JS 실행 없음.
- 파일 교체를 통한 저장과 쓰기 직렬화로 동시 업로드·다운로드 유실 방지.
- 업로드 600KB, 루틴 파일 500KB, 기기별 게시물 50개, 서버 1,000개 제한.
- 게시물 목록 페이지당 12개. 소유자만 삭제 가능. 요청 빈도 제한.
- API `GET /health`, `GET/POST /posts`, `GET/DELETE /posts/:id`, `POST /posts/:id/download` (접두사 `/api/community`).
- 화면의 Routines 제공 템플릿은 실제 사용자 게시물·다운로드 수로 집계하지 않습니다.

개발용 시뮬레이터·가상 입력·API 테스트 화면은 제품에서 제거했습니다. 코드 회귀 검사는 계속 유지하며 `npm test`, `npm run test:ui`, `npm run test:production`으로 실행합니다.

화면 검사는 실행 중인 개발 서버를 종료한 뒤 실행하세요. 검사 서버는 `test-results/community-data`를 사용해 실제 커뮤니티 게시물과 분리합니다. Playwright 전용 Chromium 대신 설치된 Chrome을 별도 headless 프로필로 검사하려면 PowerShell에서 `$env:PLAYWRIGHT_CHANNEL='chrome'`을 지정할 수 있습니다.
