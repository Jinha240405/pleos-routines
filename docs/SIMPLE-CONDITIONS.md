# 조건 편집 0.5 설계

기존 Pleos 색상·Asta Sans·48px 이상 터치 영역을 유지한다. 조건의 기본 화면은 `확인할 상태 / 비교 방식 / 기준값` 한 줄로 읽히는 카드와 자연어 미리보기만 보여 준다. 숫자·변수·연산 종류의 중첩 메뉴는 기본 화면에서 제거한다. 모바일은 같은 순서를 세로로 배치한다.

상태 선택은 자주 쓰는 차량 상태, 현재 실행 경로에서 앞서 읽은 결과, 이번 시작 이벤트, 다른 차량·연결 상태로 구성한다. 결과는 블록 ID로 연결해 이름 입력 없이 선택하며, 같은 이름의 조회 두 개도 서로 덮어쓰지 않는다. 위치 등 복합 응답은 알려진 필드 또는 실제 응답의 세부 항목을 표시한다. 데이터가 없는 미확인 필드 구조를 임의로 만들어 내지 않는다.

여러 조건은 `모두 맞으면 / 하나라도 맞으면`과 조건 추가로 구성한다. 기존 복잡한 논리식·계산식은 고급 편집에서 손실 없이 유지한다. 기본 선택으로 전환할 때 저장하지 않은 변경을 취소할 수 있어야 한다.

조회 결과를 따로 저장하도록 요구하지 않는다. 기존 변수 기반 파일은 계속 실행하고, 새 연결은 블록별 결과 참조를 사용한다. 이후 블록, 다른 시작 흐름, 실행이 보장되지 않는 반대 분기의 결과는 기본 선택 목록에서 제외한다. 저장 결과는 매 실행마다 초기화한다.

템플릿은 출발·쾌적함·충전·도착 상황별 실용 예제로 구성한다. 템플릿을 선택하면 독립 사본이 생기며 이벤트는 사용자가 감지를 시작한 후에만 실행한다. API 예제의 시뮬레이션 입력은 테스트 모드에만 주입하고 실제 응답과 구분한다.

검증: 결과 연결의 범위·중복·재실행·가져오기 호환성, 터치만으로 조건 작성·실행, 템플릿 분기 실행, 1440px/375px 3회 캡처, APK 오프라인 CSP.
